# 論文・卒業論文 執筆総合ガイドライン

本ドキュメントは、お茶の水女子大学 理学部情報科学科 伊藤研究室のゼミ資料「はじめての論文執筆（2025年12月17日版）」と、慶應義塾大学 理工学部物理情報工学科 渡辺氏の講義資料「主に数値計算系の卒論の書き方」の内容を統合し、重複を整理した論文執筆の網羅的ガイドです。

---

## 1. 論文執筆の心構え・基本原則

### 1.1 最重要事項と目的
* **期日厳守とバックアップ**：卒論・論文において最も重要なのは「期日までに完成版を提出すること」と「バックアップを確実にとること」である。
* **一貫したストーリー**：単なる「自分ががんばったこと」の羅列ではなく、「読者が知りたいこと」を書き、「一つの論文」として一貫したストーリーを持たせる。研究には「流れ」があり、先行研究の文脈の中で本研究がどのような位置づけを持ち、次の展開へどう繋がるかを明確にする。
* **結果の誠実な記述**：「当初の見込みに沿った結果が出ること」だけが成功ではない。「やったけれどできなかった」というネガティブな結果も、後進の試行錯誤を減らし「人類の知に資する」立派な成果である。変に取り繕わず誠実に記述する。

### 1.2 論文を通して示すべき「3つの素養」
1. **魅力ある研究をできる素養**：研究の価値や面白さを売り込み、読者を「つかむ」記述を心がける。
2. **几帳面な素養**：関連研究を丁寧に調査し、指定された書式・注意事項を厳守して整然とした文書を作成する（「参考文献の乱れは著者の乱れ」）。
3. **理系学生としての素養**：数式、アルゴリズム、フローチャート、図解、数値的証拠を盛り込み、論理的・一意的に記述する。

### 1.3 研究職を目指さない人にとっての意義
* 誰が読んでも同じ意味にとれる文章（設計書・仕様書・報告書等）を書く訓練になる。
* 書式に沿った整然とした文書作成能力はビジネスでも評価につながる。
* 論文の「書き方」を理解することで、他者の論文を「速く正確に読むスキル」が身につく。

## 2. 論文の全体構成とストーリーの組み立て

研究論文は、全体像（背景・目的）から詳細（手法・結果）へ入り、再び全体像（考察・結論）へ戻る**U字型（またはV字型）構造**をとる。

### 2.1 全体のストーリー構成テンプレート
1. **[大きな背景]**：達成したい大きな目的Aは何か。
2. **[小さな背景]**：目的Aを達成するためのサブタスクは何か。
3. **[先行研究紹介]**：これまでどのような研究が行われてきたか。
4. **[問題提起]**：先行研究にはまだどのような不満・課題が残っているか。
5. **[目的の説明]**：その不満をどのような形で、どの程度改善したいか。
6. **[手法の説明]**：具体的な改善方法（提案手法）。
7. **[結果の説明]**：不満はどれくらい解決できたか。
8. **[まとめと考察]**：この研究は研究の流れの中でどんな意味を持ち、先にどんな展開があるか。

## 3. 各章の執筆ポイント

### 3.1 第1章：序論（背景・目的・概要）
* **役割**：読者に「この研究は必要だ」と納得させる導入文。専門外の人にも読みやすく明瞭な構成にするが、過度な一般化による曖昧さは避ける。
* **論旨展開の一例（起承転結）**：
  * **【起】** 研究分野の背景・歴史・前提（なぜ注目されているか）。
  * **【承】** 自分の研究課題に関する最新の研究動向（なぜ既存手法が主流か）。
  * **【転】** 残されている問題点・課題（なぜ改善が必要か、どのくらい改善したいか）。
  * **【結】** 提案内容や実行結果の概要（詳細は踏み込みすぎない）。
* **意識すべき観点**：
  * もし自分の成果が世の中になければ何が不足しているか、同じことの実現がどれだけ難しいか。
  * ターゲットユーザは誰で、どのような科学的貢献・実用的価値があるか。
* **実行結果との整合性**：「1章で掲げた課題・自説を、結果の章で検証する」構成を徹底する。結果がそこまで至っていない場合は、1章の書き方を現状に合わせる。
* **形式的な習慣（分野固有）**：
  * **1ページ目冒頭の図1**：システム構成や代表的な実行結果を冒頭に置き、研究をアピールする。キャプション（図の題）はそれだけで概要がわかるよう説明的（descriptive）に長く書く。
  * **研究の要点を箇条書き**：`Goal`（大きな目標）、`Task`（実現したい処理・操作）、`Requirement`（必要な要件）、`Contribution`（研究の貢献・新規性・有効性）を前半で明確にし、後半でこれらを検証する。末尾に次章以降の構成を述べるのも一般的。

### 3.2 第2章：関連研究（サーベイ）
* **先行研究の構造化**：単に論文を羅列するのではなく、あらかじめ明快に分類して段落を分け、なぜその研究を紹介するのか読者にわかるようにする。
* **差異と課題の明示**：各先行研究に残された課題と、自分の研究がそれとどう異なるかを明確にする。
* **調査範囲**：日本語文献だけでなく、早期から英語の論文も調査・引用する。

### 3.3 第3章：提案内容・手法詳細
* **トップダウンな説明**：まず研究のコア部分の「全体像」を説明し、その後に個々の要素技術を説明する。要素技術の説明順は「開発順」「ユーザ操作順」「計算機処理順」のいずれかで首尾一貫させる。
* **再現可能な記述（一意性の確保）**：文章だけに頼らず、数式・アルゴリズム・図表・フローチャートを多用し、読者が同じ手法を再現できるように書く。
* **普遍的な内容にとどめる**：開発環境・実行環境、実験データの詳細、ユーザテストの参加者内訳などの個別事情はここには書かず、原則として「実行結果」の章に書く。

### 3.4 第4章：実行結果・考察
#### 実行結果
* **役割**：前章で説明した理論や機能が適切に動くことを実証する（手法の説明を混在させない）。実験や検証の過程も再現可能に記述する。
* **定量的評価**：画像だけでなく、誤差、計算時間、先行手法との性能比較、ユーザテストの集計結果などを**数字**で評価する。
* **執筆チェックリスト**：実験の目的・目標 / 開発・実行環境 / 参加者の人数・属性 / 実験の工程・手順 / 実行結果（数値・画像） / 統計的分析手法 / 参加者のコメント。

#### 議論・考察
* **序論との対応**：序論で提示した問題・目的に対する答えを明確に述べる（例：「目標の40%改善に対し20%の改善を得たため、実用化にはさらなる改善が必要」など）。
* **多角的な分析**：結果のどこが・なぜ良かったのか（あるいは悪かったのか）、先行研究と比べてどう優れているのかを解説する。
* **位置づけと展望**：本研究が「大きな研究の流れ」の中でどのような科学的・技術的知見や貢献をもたらし、この先にどのような新しい展開があるかを論じる。

### 3.5 第5章：まとめ・今後の課題
* **アブストラクト・概要・まとめの機能的違い**：
  * **アブストラクト**：本文から分離して単独で読まれる全体の要約。背景・提案だけでなく**実行結果にも言及**する。本文にないことは書かない。
  * **概要（序論）**：初めて読む人のための導入。問題設定と提案の方向性を示す。
  * **まとめ**：論文を読み終えた人への復習と、実行結果から得られた新しい知見・結論の総括。
* **今後の課題**：2〜3日で解決できる小さな課題は省き、本質的で重要な課題を厳選する。関連性の高いものをまとめ、短期的な課題から長期的な課題の順に並べる。

## 4. 論文中の文章表現・言葉遣い（日本語のローカルルール）

理工系文書では「誰が読んでも同じ意味にとれる（一意性が高い）文章」が求められ、曖昧さや情緒を排除する。

### 4.1 文法・表現の基本
* **主語の明記**：主語を省略せず、「本論文」「本報告」「本手法」「我々」「筆者らは」を正確に使い分ける。
  * *本論文*：論文誌、修士論文、博士論文。
  * *本報告*：口頭講演、ポスター発表。
  * *本手法*：手法自体を指す場合（「本研究」は学外原稿では可能な限り上記に置き換える）。
* **時制と単純な文法**：常体（だ・である調）で書く（謝辞の敬語は例外）。普遍的な理論やアルゴリズムは「現在形」、実験手順や結果は「過去形」を用いる。不必要な進行形や回りくどい表現は避ける（例：「実験します / 実験していく / 実験を行う」→「実験する」）。
* **助詞の厳密な使用**：目的語に「は」「が」を使わず、「を」「に」を正しく使う（例：「ドアは閉めておきます」→「ドアを閉めておきます」）。

### 4.2 語彙・表記のルール
* **日常的・主観的な形容詞や曖昧な名詞の排除**：
  * 「わかりやすい」「見やすい」は主観的で自明なため禁句とし、「短時間で理解できる」「誤解を招かない」など具体的に形容する。
  * 入力や出力を単に「データ」と呼ぶのを避け、数値（スカラ/ベクタ）、文字列、画像、音声など具体性のある単語を選ぶ。
* **あえて平仮名を使う単語**：漢字より読みやすくなる以下の語は平仮名表記にする。
  * 出来る→できる / 従って→したがって / 又は→または / 殆ど→ほとんど / 更に→さらに / 挙げる→あげる / 基に→もとに / 同士→どうし / 〜な事→〜なこと / 〜な所→〜なところ
* **JIS規格によるカタカナ表記**：3音以上のカタカナ語は原則として語尾の長音符号「ー」を省く（例：「ユーザーインターフェース」→「ユーザインタフェース」）。
* **句読点・括弧・英数字の形式**：
  * 句読点は「、。」ではなく全角の「，．」を用いる（半角の `,` `.` は不可）。
  * 括弧書きや参考文献番号は句読点の**前**に置く（例：`○ 伊藤は提案した[1]．` / `× 伊藤は提案した．[1]`）。
  * 英数字・数式・図表番号は原則として半角を使用する。
  * 段落の最初は1文字字下げする。

## 5. 引用・著作権・生成AIの取り扱い

### 5.1 引用の原則と著作権（著作権法第32条1項）
* **引用の4要件**：①必然性（執筆に不可欠）、②明瞭区別性（カギカッコや `quotation` 環境で引用部分を明確化）、③主従関係（自分の文章が質・量ともに主）、④出典の明示。
* **引用の有無による意味の違い**：引用のない記述は「著者のオリジナル」とみなされる。
  * `Aという手法にはBという問題がある．` → 著者の意見。
  * `Aという手法にはBという問題がある[4]．` → 文献[4]の指摘。
  * `Aという手法にはBという問題がある[4-8]．` → 多くの研究者の共通認識。
* **引用元の選定**：原則として書籍か査読付き論文を引用する。
  * ウェブサイトの引用は極力避け、サイト内で引用されている**原典**にあたる。
  * `arXiv` 論文を引用する際は、国際会議や論文誌で正式に出版されていないか検索して確認する。
* **コピペ厳禁**：文献を読んで自分の言葉で理解して書く。重要語句や概念の説明をAIやWikipediaに頼らず、教科書や論文を読み込む。

### 5.2 インターネット上の画像利用
* 検索で見つけた画像は著作権者が不明確であり、企業サイト等の画像は事前の書面許諾が必要なため、原則使用しない。必要な図は自作する（「いらすとや」等の多用も卒論では避ける）。

### 5.3 生成AIの活用ルール
* **禁止事項**：AIが生成した文章をそのまま転載すること（学会規定違反、著作権リスク、誤りや論理破綻、ありきたりで定型的な表現「近年〜」等の混入を防ぐため、また自身の文章作成訓練のため）。
* **許容される活用例**：適切な参考文献の探索、数式の正しさの確認、自分が書いた文章の推敲・修正案の検討。AIを用いた場合も必ず自分で全編を読み返し、責任を持って修正する。

## 6. 図表・データの作成と管理（テクニカルガイド）

### 6.1 データの分離と自動化（再現性の確保）
* **計算と描画の分離**：シミュレーション・計算プログラムと、グラフ作成プログラムを分ける。計算結果を中間データファイル（`.dat` 等）に出力し、そこから作図スクリプトで図を生成する（フォントや線の太さの微調整を何度も行うため、また生データとスクリプトを保管して改変・捏造の疑いを晴らすため）。
* **ファイル名の統一と一括生成**：`pressure.dat` と `pressure.plt`（または `.py`）から `pressure.pdf` を生成するように名前を揃え、`Makefile` やシェルスクリプトでコマンド一発（`make` 等）ですべての図が再生成できるようにする。

### 6.2 わかりやすいグラフ・図の作り方
* **1図1メッセージ**：複数の情報を詰め込まず、図一つにつき主張は一つにする。
* **比較の工夫**：比較したい対象（手法XとYの精度など）は別の図に分けず、同じ図にプロットする。逆に「高い方が良い指標（精度）」と「低い方が良い指標（計算時間）」を1つのグラフに混在させない。
* **相対値（性能比）の活用**：絶対値の比較で差がわかりにくい場合は、既存手法との性能比（Relative Performance）をプロットする。
* **適切な軸の範囲**：変化を誇張するために縦軸の途中から切り取る（例：0.995〜1.04）のは不適切であり、原則として0から範囲をとって正当な比較を示す。
* **概念図（ポンチ絵）**：複雑な手順や実験セットアップは概念図で示す。PowerPoint、Adobe Illustrator、draw.io 等で作成し、編集可能な**元ファイル（`.pptx`, `.ai`, `.drawio` 等）も一緒にバージョン管理**する。

### 6.3 フォーマット・配置ルール
* **ベクタ画像の推奨**：拡大縮小で劣化しないベクタ画像（PDF, EPS, EMF等）を使用する。画面キャプチャや単純なコピペによるラスタ画像化は避ける。
* **キャプション（題名）と番号**：すべての図表に通し番号と題名をつけ、本文中で必ず引用・説明する。
  * **図の題名**：図本体の**下**に配置。
  * **表の題名**：表本体の**上**に配置。
  * 左右に並べる図は別番号にせず `図1(左)(右)` のように表記する。
* **配置場所**：本文中で引用した段落の直後、またはその近辺のページ上部・下部に配置する。

## 7. 執筆環境・バージョン管理・バックアップ

### 7.1 執筆ツールの選択（LaTeX vs WORD）
* **LaTeXを強く推奨するケース**：Mac環境、複数PCでの作業、数式の多用、長大な論文（修論・博論）、図番号・参考文献（BibTeX）の自動管理をしたい場合。
* **WORDを使うケース**：非情報系の学会等でWORDのテンプレートしか提供されない場合。
  * *WORD書式設定の基準*：題名・章題名はゴシック体＋Arial（太字）、本文は明朝体＋Times New Roman（両端揃え）、数式はすべて数式エディタを使用。
* **オンライン環境（Overleaf等）**：共著者との協調添削に非常に有効だが、サーバ障害やタイムアウトに備え、ローカル環境にもLaTeXを導入してバックアップを保持する。

### 7.2 Git / GitHub による管理とバックアップ
* **バックアップの鉄則**：ローカルの別フォルダやUSBメモリへのコピーは信用せず、最低でも毎日（理想は15分〜1時間ごと、仕事のひとかたまりごとに `commit` & `push`）リモートリポジトリへバックアップする。パスワード入力の手間を省くため `ssh-agent` を設定する。
* **リポジトリの分離**：
  1. **卒論執筆用リポジトリ**：TeXファイル、bibファイル、図のファイル、図を作るためのデータ、作図スクリプト、ポンチ絵の元データ。
  2. **プログラム開発用リポジトリ**：プログラムソース、インプットファイル、ジョブスクリプト等（※計算の出力データや巨大なダンプファイルはリポジトリに入れない）。

## 8. 執筆プロセス・共著者とのやり取り・原稿の再利用

### 8.1 執筆の進め方と添削依頼
* **途中段階からの執筆**：研究結果がすべて揃う前から序論や関連研究の下書きを始め、共著者とストーリーや実験の優先順位を議論する。
* **添削依頼のマナー**：共著者は多忙であるため、提出期限直前ではなく十分な余裕を持って依頼する。学外の共著者へは、指導教員任せにせず筆頭著者（学生本人）から直接連絡・依頼を行う。

### 8.2 学内原稿と学外原稿の違い（再利用時の注意）
スライドやポスターを含め、発表形態に応じて以下を必ず修正する。

| 項目 | 学内原稿（卒論・修論要旨、ゼミ資料） | 学外原稿（学会・研究会・論文誌） |
| :--- | :--- | :--- |
| **著者名** | **単著**（自分の氏名のみ） | **連名**（研究に貢献した共著者・指導教員を列挙） |
| **所属** | 学科名、研究室名、学年などを前例に従い記載 | 大学名・学科名・研究科名を明記（研究室名・学年は原則削除。進学後の学部表記ミスに注意） |
| **謝辞** | 研究室外でお世話になった人すべてに記載（指導教員への謝辞は研究室方針による） | **共著者は謝辞から外す**。科研費等の学外予算の記載要否を指導教員に確認する |

### 8.3 学会原稿のステップアップ（ページ数増加時の更新点）
短い原稿（1〜2ページ）から研究会・国際会議（6ページ〜）・論文誌へ発展させる際、著作権譲渡の観点からも同一原稿の使い回しは避け、以下の点を拡充する。
* **題名**：研究の進展・更新部分を強調するキーワードを取り入れ、発表ごとに少しずつ更新する。
* **背景・概要**：先行研究の課題と解決策、提案手法の特徴、結果の概要を詳細化し、末尾に論文構成を追記する。
* **関連研究**：ページ数に比例して増やす。単純な追記で構造が崩れたら章全体を書き直す。
* **提案手法**：読者が技術を完全に再現できるレベルまで数式やアルゴリズムを詳細化する。
* **実行結果・考察**：検証項目を増やし、なぜ良い/悪いのか、先行研究との比較、課題の原因と解決策まで深く考察する。
* **まとめ・今後の課題**：投稿のたびに毎回書き直す。研究の進捗に合わせて「今後の課題」を最新の状態に更新する。
* **参考文献**：ページ数や研究の進展に合わせて最新の文献を追加する。

### 8.4 著者順（オーサーシップ）の決定原則
情報科学分野では原則として**貢献度の大きい順**に並べる（伊藤研の基準例）：
1. **筆頭著者**：研究の主体となった学生・研究者。
2. **指導教員より前の共著者**：発案に大きく貢献した人、直接手を動かして研究の根幹や代替不可能な材料（プログラム・データ）を提供した先輩学生や若手研究者。
3. **指導教員**
4. **指導教員より後の共著者**：助言や情報提供が中心の共同研究機関の職業研究者、留学先等での短期的な共同研究者。
