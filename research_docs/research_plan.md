# 研究計画

出典の略称は `README.md` を参照。ここでは決定済みの内容を整理する。未確定の事項は `research_decisions.md` と `analysis/open_issues.md` にある。

## 1. テーマ

「EC決済ページにおけるカード情報送信の消費者側観測可能性の評価」（[S P9]）
一行で言うと、消費者側ブラウザ拡張（MV3）が、決済方式ごとにカード情報の送信をどこまで観測・判定できるかを測定する。（[H §0]）

## 2. 背景・問題意識

- 【文献】Magecart（Webスキミング）は、正規ECサイトに不正に埋め込まれたスキマー（JavaScript）が、入力されたカード情報を攻撃者サーバーへも送る攻撃。消費者は正規サイトで買い物をしていても被害に遭う。（[S P4-P7]）
- ECサイト側の防御策は複数ある一方、消費者側ができることは「信頼できないサイトを避ける」が中心。（[S P8]）
- 消費者側観測点で「何が守れ、何が原理的に守れないか」が不明。（[S P9]）
- 先行研究 Bower (2019) は消費者側 Chrome 拡張でスキマーを検知・ブロックした。研究者の位置づけ（[S P15]）では、Bower は ECサイトの形式（入力DOM、宛先、frame）を区別していないため、実装形式や観測方法ごとの限界が明らかでない。
  - 注意: これは研究者の整理である。Bower 自身は iframe 内フォームの入力収集（[B §3.3]）や、偽 iframe の挿入の検出（[B §3.4.3]）を扱っている。「区別していない」が具体的に何を指すかは、資料から判断できない。（`literature/bower_2019.md`）
- Manifest V3 では通信を止める能力が削られ、観測が中心になった。Bower のブロック方式は MV3 で成立しない（【文献】外部仕様に基づく。一次資料は本リポジトリにない）。（[H §10]）

## 3. 研究目的

- 消費者の干渉できる領域であるブラウザ拡張で、どの程度まで観測が可能かを、ECサイトのパターンごとに明確にする。（[S P9]）
- 【決定】検知器の精度向上ではなく、観測・判定の境界（どこで失明するか）を示す。方針転換はしない。（[H §1]）

## 6. 研究の貢献（主張したい点）

【決定】資料が示す、先行研究に対する位置づけ（[H §9]）:

- **新規性を示す部分:**
  - Bower が将来課題とした「個人情報の重大度ランク付け（正規/悪性の分離）」に、本研究の L4（宛先 allowlist での判定境界の定量）を接続する。
  - Bower の偽陽性実測（約1.4%）を、「正規の第三者送信が誤検知される」現象の実在証拠として引用する。（引用の妥当性に論点あり。`analysis/open_issues.md` E-6）
  - MV2前提の Bower を、MV3の観測可能性から捉え直す。
- **新規性にできない部分:** 消費者側拡張で Magecart に対抗すること、iframe 内送信の観測、Base64/難読化/暗号化 exfil の扱い、precision/recall での検知器評価。
- 日本固有の文脈（非保持化義務・3Dセキュア義務化）を新規性として重視する。（[H §3]）ただし根拠資料は【未確認】。

卒論として現時点の実測で主張できる範囲は `analysis/findings.md` を参照。
