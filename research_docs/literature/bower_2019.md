## 2. 研究目的

【文献】ページが Magecart 型スキミングに感染しているかを判定し、悪意あるコードの実行を阻止できるシステム（Chrome 拡張）の設計・実装。サイトのバックエンドにアクセスせず、受動的に動作し、人手の介入を最小限にする。高い適合率と再現率を目指す（[B §1.2]）。

## 3. 手法

【文献】

- 動的解析: `webRequest` の `onBeforeRequest` で送信 body を監視し、機微な値が含まれ宛先が不審なら request を cancel する（[B §3.4]）。
- クロスオリジン iframe: 親フレームが全子フレームの入力を収集する。SOP のため、postMessage で子フレームへ入力の問い合わせを送り、再帰的に集める（[B §3.3 Identifying User Data]）。
- 静的解析: ヒューリスティック（リファラによるクローキング、ライブラリ内への潜伏、難読化コード等）。
- 難読化・符号化への対処: エンコード（Base64等）の復号、暗号化リクエストの扱い（目次: ブラインディング係数、非決定性の排除、リクエストの再生）。【未確認】詳細は未読。
- 偽 iframe の挿入の検出（[B §3.4.3]）。

## 4. 結果

【文献】

- Netcraft のスキマーフィード検証（14日間で681サイトがフラグ付け、そのうち感染が残っていたもの。本文は「242」と「240」が混在）: TP 238 / FP 6 / TN 433 / FN 4。論文は適合率 0.983、再現率 0.975 と記載（[B §4.2.2、表8]）。
- 偽陽性率（FPR）は 1.4% をわずかに下回る（約70件に1件の正規リクエストが誤ブロック）。偽陽性の原因は、住所オートコンプリートで部分住所を第三者サービスへ送る機能、フォームの値を含むマウス位置等をトラッキング・広告会社へ送るスクリプト（[B §4.2.2]）。
- 偽陰性4件は、フォームフィールドを認識できなかったため（`stopPropagation` の可能性）。
- 高価値サイト（British Airways、Newegg、Ticketmaster、Uniqlo）: スキマーのリクエストはすべてブロックされ、他のリクエストはブロックされなかった。真陽性率 100%、偽陽性率 0%（サンプルは小さい）（[B §4.3.2]）。
- ユーザビリティ: 一部のサイトで性能上の問題・応答停止（[B §5.1]）。

## 5. 限界・将来課題

【文献】

- 将来課題（[B §5.2]）: 集中型スキマーDB、自動クロール、置換型 Base64 の検出、ライブラリ不一致検出の改善、高度な静的解析、ドロップサーバーのヒューリスティック、個人情報の重大度（Private Information Severity）。
- 個人情報の重大度: メールアドレス等とカード番号は重大度が違う。種類で順位付けして、通すリクエストを決める案（[B §5.2.7]）。
- 自動クロールには、チェックアウト到達の難しさ（アカウント作成、カート条件等）がある。（[B §5.2.2]）
- 【未確認】[B] 第5章の「考察（限界）」の本文（ソースコードが入手可能であること、偽陽性）は未読。

## 7. 引用時の注意（【未確認】・論点）

- **適合率と再現率が標準定義と逆。** 表8（TP 238, FP 6, FN 4）から、標準定義では適合率 = 238/244 ≒ 0.975、再現率 = 238/242 ≒ 0.983。論文は適合率 0.983、再現率 0.975 と記載。[BJ p.36] の訳注も指摘。[S P14] は論文の表記をそのまま引用。
- 【決定】引用方針（D46）: 原文の数値を引用し、標準定義との食い違いを注記する。再計算値は「再計算」と明記する。
- 感染サイト数が本文で「242」と「240」。結論（§5.1）は 97.5% を「真陽性率」と呼ぶ。
- 偽陽性 1.4% の内訳は、住所補完、トラッキング、メール購読ポップアップ等で、カード番号を含む正規送信の誤検知ではない。[H §9] の「正規の第三者送信が誤検知される現象の実在証拠」という引用は、この範囲で解釈する必要がある。
