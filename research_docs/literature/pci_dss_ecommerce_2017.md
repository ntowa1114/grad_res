## 2. 目的と本研究での役割

- 【文献】EC の実装形態ごとの PCI DSS 上の位置づけとセキュリティのベストプラクティスを説明する文書。
- 本研究での使われ方: 発表資料 [S P21] が、EC実装を5形式に分類する根拠としている。自作EC（正規）の実装方式の根拠。[S P22]（「PCI DSS の仕様に従い、実験対象のECサイトのプロトタイプを実装」）
- 【未確認】[H] はこの文書を引用していない。4分類（[H §3]）との対応は資料にない。

## 3. 文書内の EC 実装分類【文献】

[PCI §2] の分類（各節の見出し）:

| 節 | 方式 | 文書の記述（読んだ範囲） |
|---|---|---|
| 2.1（p.8） | URL Redirects | 決済ページを第三者（PSP）にホストさせ、顧客をリダイレクトする |
| 2.2（p.10） | iFrame | PSP が提供する決済フォームを加盟店ページに iFrame で埋め込む。カード情報は PSP の iFrame が受け取る。SOP に依存して一定の安全性を提供する。SAQ A の対象になり得る |
| 2.3（p.13） | Direct Post Method (DPM) | 加盟店のサイトが決済ページを生成し、カード情報は直接 PSP へ送る。加盟店サーバーが決済フォームを管理するため、リダイレクト・iFrame より加盟店侵害のリスクが高い。SAQ A-EP の対象になり得る |
| 2.4（ページ未確認） | JavaScript Form | DPM に似る。決済ページは加盟店サイトから来て、入力されたカード情報は DPM と同様に PSP へ直接送られる |
| 2.5（p.17） | API | システム間のデータ送信。加盟店システムがカード情報を扱う。SAQ D の対象になり得る |

- §2 冒頭の一覧には、上記に加えて「iFrame以外のタグによる埋め込みコンテンツ」と「加盟店ゲートウェイ + 第三者の埋め込みAPI」も挙がっている。
- §6 にケーススタディがある（6.1 完全外部委託のリダイレクト、6.2 完全外部委託の iFrame、6.4 加盟店管理の API。6.3 は未確認）。

## 4. 本研究との関係

- 【文献】iFrame 型が SOP に依拠している点は、[P 実験1]（親 JS から `contentDocument` が `null`）と対応する観察である。ただし [P 実験2-3] では、拡張機能は SOP の制約を受けずに iframe 内の送信を観測できた。
- 【決定】2026-10-24 に研究者が、決済方式の分類として PCI の5型を採用すると決定した（`../research_decisions.md` C6）。
- 【未確認】PCI の5型と [H §3] の4分類の対応表は存在しない。`../analysis/open_issues.md` E-1 に記録。
- 【文献】原本で確認した範囲（p.8-18）: 各方式でカード情報が通る経路は次のとおり。リダイレクト型は顧客ブラウザから PSP のページへ直接（加盟店は扱わない）。iFrame型は PSP の iFrame が受け取る。ダイレクトポスト型は加盟店のフォームから PSP へ直接送る（フォームは加盟店が生成）。JavaScriptフォーム型は PSP の JavaScript が加盟店ページ内にフォームを作り、PSP へ直接送る。API型は顧客ブラウザから加盟店サーバーへ送り、加盟店サーバーが PSP へ送る（[PCI §2.1〜2.5]）。
- 【未確認】[H §3] の「JSトークン型」と PCI の「JavaScript Form」が同じ概念かどうかは、資料から判断できない。
