## 2. グループの定義【文献】

- 「少なくとも7つのグループ」の総称が Magecart（p.2）。ただし本文で詳述するのは6グループで、**Group 1 と Group 2 は同一グループとして統合**されている（p.4, p.10）。したがって詳述されるのは Group 1(+2)、3、4、5、6、7 の6つ。
- グループを分ける基準は3カテゴリ（p.7）: ①インフラが固有（IP、ドメイン、サーバー構成）、②スキマーが固有（難読化技法、機能・データ取得の方法、読み込み方）、③標的の取り方が固有（標的群、侵入方法、スキマーの設置方法、被害者への到達方法）。
- 【解釈】[S P23] は「スキマーを7つの項目にグループ分け」「主なグループ分けの要素: 送信手段（POST/GET）、決済画面・フォームの識別ロジック、フォームデータの収集・操作手法、難読化・対解析・隠蔽技術」と書く。[RQ] 本文の分類基準（上記3カテゴリ）とは書き方が違う。E-15 に記録。

## 4. 本研究との関係

出典: 研究者の方針（2026-10-24 の会話、`../research_decisions.md` C7）。

- 【決定】スキマーモデルは1つに絞る。ベースは [RQ] のグループ定義で、カスタマイズも可。（Q10 は未決）
- 【解釈】[RQ] の本文から読み取れる、観測に関係しそうな違い（5型への適用は [RQ] に書かれていない）:
  - **送信方法**: POST（Group 1、3、4、5）と、画像要素による GET（Group 7）。`fetch`、XHR、`sendBeacon` といった API の違いは、読んだ本文の範囲では区別されていない（【未確認】）。[H §4] の軸1（fetch / XHR / 画像GET / sendBeacon / WebSocket）は、[RQ] で裏付けられるのは POST と画像 GET まで。
  - **宛先**: スキマーの配信元と同一のサーバー（Group 1）、専用の drop server（Group 3、5）、被害サイトの URL に似せた宛先（Group 4、6）、侵害済みの他人のサイト（Group 7）。[H §4] の軸2（攻撃者サーバー / 乗っ取り実在サイト風 / 正規サービス装い）と対応づけられるが、「正規サービス装い」に当たる記述は、読んだ範囲では確認できていない。
  - **符号化**: プレーン（Group 1 は記載なし）、JSON（Group 3）、URL エンコード（Group 4）、Base64（Group 5、7）。スクリプト自体の難読化（Group 4、5）と、送信データの符号化は別の話。
  - **カード情報の取得方法**: 入力欄の値の読み取り（Group 1、5、6、7）、フォームのフィールドID一覧（Group 3）、**決済フォームの置き換え（Group 4）**。【解釈】決済フォームが加盟店のページの外にある型（リダイレクト型、iFrame型）で、悪性送信が成立するかは、この取得方法に依存する可能性がある。[PCI p.12] は、加盟店サイトを侵害した攻撃者が iFrame の代わりの内容を作れると述べている。[RQ] がこれを5型と結びつけて論じているかは、読んだ範囲では確認できていない。
  - **対解析**: Group 4 のみ詳述（指紋、実行時間の計測、条件付き配信）。[H §4] は対解析を別枠にする方針。
- 【未確認】[RQ] は、決済方式の5型への言及を、読んだ範囲では含まない（Group 3 が決済事業者のフォームの一覧を持つ記述のみ）。
