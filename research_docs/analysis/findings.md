# 判明したことと、主張の根拠の対応

実験結果から判明したこと、卒論で主張できる範囲（候補）、根拠を整理する。
出典の略称は `README.md` を参照。実験の詳細は `../experiment_index.md`。
「主張候補」は資料から読み取れる範囲での整理であり、研究者の決定ではない。最終的な主張は研究者が決める。

## 2. 卒論で主張できること（候補）と根拠の対応

| 主張候補 | 根拠 | 強さ | 不足している裏付け |
|---|---|---|---|
| (a) MV3 拡張の案A/案Bは、平文送信の場合、別オリジン iframe 内からのカード送信を L1〜L3 まで観測できる | F1, F2（[P]） | PoC の範囲で実測 | 他の方式、送信手段、反復、実環境（eTLD+1・証明書） |
| (b) 案Aの成否は、content script の world と注入範囲（`all_frames`）に依存する | F2, F3（[P]）、F10（[H]） | MAIN true は実測。ISOLATED は実測だが条件の詳細が不明。`all_frames=false` は予測 | 本実験では追加の測定をしない（D42） |
| (c) 宛先の照合（PoC では PSP 宛だけを許可）だけでは、正規と悪性を一意に分離できない | F6（[P 実験4]） | 正規側の1ケースのみ実測 | 悪性（スキマー検体）を使った L4 の測定 |
| (d) MV3 では、Bower のブロック方式（body 照合による request の cancel）は成立しない | [H §10]（外部仕様） | 一次資料がリポジトリにない | Chrome 公式ドキュメントでの確認 |
| (e) 観測可能性は決済方式によって異なる | F18〜F20（L1〜L3、L4a: **差は出なかった**。ブラウザを通る送信は全て ○。外縁③は別扱い）と F22・F23（**L4b: 差が出た**。ダイレクトポスト型・JavaScriptフォーム型は正規送信を誤判定。iFrame 型・API 型・URLリダイレクト型は正解） | 5型・案A・案B・各3回で実測。ただし自作EC・平文・`fetch` のみ。L4b のルールは1つ | 実在の PSP（実 Stripe 版。D12）、他の判定ルール、パス・本文を使う判定。主張は「この条件・このルールで、L4b に型による差が出た」までで、「方式によらず」とも「方式によって決まる」とも言い切れない |

【解釈】PoC の範囲（(a)(b)(c)）に加え、本実験の測定で、自作EC・平文・`fetch` のみの条件では、案A・案Bとも、ブラウザを通る送信を L1〜L3 と L4a（正規宛先を渡す判定）まで観測できた（F18〜F20）。一方、正規宛先を渡さない判定（L4b）では、ダイレクトポスト型・JavaScriptフォーム型で、正規送信を判定できなかった（F22・F23）。「どこで見えなくなるか」の境界は、観測（L1〜L3）ではなく、判定（L4）で、決済方式によって現れた（【解釈】）。符号化（(f)）など、他の条件は未測定。
